3 Пример программы и методики испытаний

        Испытательная конфигурация: ASP.NET Core .NET 8, тестовый
конфигурационный ключ X-API-Key, среда Production, временное in-memory
хранилище. Сначала выполняются автономные unit-тесты валидации, затем
интеграционные проверки HTTP и безопасность среды, далее пробная
эксплуатация на учебных данных. Критерии успешности: все обязательные
тесты PASS, неустранённых Critical/Major нет, актуальные версии тест-кейсов
и документации зафиксированы в Git.

4 Рекомендации по адаптации документации

     • Оставить единое ТЗ по ГОСТ 19.201-78 и идентификаторы требований
     R-01…R-05.
     • В документах о тестировании использовать терминологию
     действующего ГОСТ Р 59792-2021; старый ГОСТ 34.603-92 цитировать
     только для сравнительного анализа.

  • Для итерационных выпусков хранить версионируемые протоколы тестов,
  CI-логи и changelog в Git; каждый тест связывать с требованием.

  • Разделять проектируемый результат и подтверждённое выполнение: до
  запуска тесты имеют статус «не выполнялись».
      Листинг — Фрагмент контроллера, связанный с приёмкой
 [HttpPost]
 public IActionResult Create([FromBody] CreateReadingRequest request)
 {
     var result = service.Create(request);
     return result.Status switch
     {
         CreateStatus.Created => CreatedAtAction(nameof(GetByMeter),
             new { meterId = result.Reading!.MeterId }, result.Reading),
         CreateStatus.Duplicate => Conflict(new { error = result.Error }),
         _ => BadRequest(new { error = result.Error })
     };
 }
