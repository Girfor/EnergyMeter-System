       Цель — провести воспроизводимый статический аудит C# исходников
EnergyMeter System с учётом соглашений о стиле кода, структуры классов и
согласованности       реализации         с         ТЗ.      Осмотрены            Program.cs,
ReadingsController.cs,       MeterReadingService.cs,           MeterReadingValidator.cs,
ApiKeyFilter.cs и намеренно дефектный эталон examples/insecure. Аудит
выполнен чтением исходных файлов; Roslyn-анализатор и dotnet build в среде
подготовки не запускались.

1 Объём и критерии аудита

       Проверки делятся на три группы: (1) C# style: PascalCase для
типов/методов, camelCase для параметров, понятные имена и XML-
документация; (2) архитектура: разделение контроллера, бизнес-правил и
хранилища, отсутствие дублирования; (3) соответствие ТЗ и безопасность:
диапазоны значений, контроль доступа, конфигурация Swagger, CSRF. ГОСТ
19.201-78 применён к полноте формулировки требований, а не как норматив
для синтаксиса C# [1].

      К CSRF относится именно автоматическая передача браузером cookie
авторизации. Для устройства, которое явно передаёт X-API-Key в заголовке,
эта форма CSRF обычно неприменима; остаются другие угрозы, включая
компрометацию ключа. Этот факт учитывается при выборе контроля [2].

4 Порядок инструментального подтверждения

      Листинг — Команды проверки стиля и тестов в рабочей среде
 dotnet restore tests/EnergyMeter.Tests/EnergyMeter.Tests.csproj
 dotnet build tests/EnergyMeter.Tests/EnergyMeter.Tests.csproj -c Release
 dotnet test tests/EnergyMeter.Tests/EnergyMeter.Tests.csproj
 # При наличии dotnet-format:
 dotnet format whitespace --verify-no-changes
      Здесь результаты перечисленных команд не представлены как
успешные. Протокол завершения следует дополнить фактическим выводом
CLI либо логом GitHub Actions после публикации.

      Проведён статический аудит конкретных исходных файлов, оформлен
чек-лист по 12 критериям и реестр пяти приоритетных замечаний. Уязвимые

обязательным этапом при сдаче.
