ВВЕДЕНИЕ

       Цель — оценить структурную сложность кода EnergyMeter System до и
после рефакторинга и объяснить эффект декомпозиции. Базовый метод взят из
Project/examples/insecure/LegacyController.cs.txt;                    итоговая         версия       —
MeterReadingService.Create() и MeterReadingValidator. Это сопоставление
специально сохранённого учебного сценария, а не история коммитов
существующего репозитория.

1 Методика расчёта

       Цикломатическая сложность по Маккейбу V(G)=E−N+2P; для одного
связного потока управления допустимо приближение «1 + число независимых
решений». В базовом Save() выявлено семь конструкций if, поэтому V(G)=8.
После декомпозиции метод MeterReadingService.Create() имеет одну условную
ветвь if и один условный оператор ?:, т.е. V(G)≈3. Сложность не исчезает из
проекта         целиком:         проверки        перенесены                  в    самостоятельный
MeterReadingValidator, где их удобно тестировать отдельно.
       Индекс поддерживаемости MI оценивался по распространённой
нормированной формуле MI=max(0,[171 − 5,2 ln(V) − 0,23 CC − 16,2
ln(LOC)]×100/171), где V — объём Холстеда, LOC — число непустых строк.
Для V применён упрощённый учебный токенизатор; полученные значения не
являются выводом Visual Studio Code Metrics. Воспроизводимый расчёт
находится в tools/metrics.py.

3 Найденные запахи кода

  • Long Method / Excessive Branching: Save() содержит цепочку проверок
  предметной области и HTTP-ответы.
  • Mixed Responsibilities: контроллер одновременно выполняет
  нормализацию, проверку, поиск дублей и сохранение.
  • Temporal Coupling: решение зависит от DateTimeOffset.UtcNow и
  затрудняет детерминированное тестирование.
  • Check-then-act race: предварительный поиск дубля в legacy-версии не
  атомарен в условиях параллельных запросов.
  • Weak Abstraction: состояние хранилища вызывается из HTTP-слоя
  напрямую.

4 Листинги refactoring before/after

      Листинг — До: монолитный метод (сокращение учебного файла)
 public IActionResult Save(CreateReadingRequest request)
 {
     if (request == null) return BadRequest();
     if (request.MeterId == null) return BadRequest();
     if (request.MeterId.Trim() == "") return BadRequest();
     if (request.ValueKwh < 0) return BadRequest();
     if (request.ValueKwh > 1000000) return BadRequest();
     if (request.ObservedAtUtc > DateTimeOffset.UtcNow.AddMinutes(5))
         return BadRequest();
     if (_repository.FindByMeter(request.MeterId).Any(r =>
         r.ObservedAtUtc == request.ObservedAtUtc)) return Conflict();
     // Прямое сохранение в контроллере
     return Ok();
 }

ЗАКЛЮЧЕНИЕ

      Показана декомпозиция монолитного метода в сервис, валидатор и
репозиторий. Для сопоставляемого метода оценочная цикломатическая
сложность снижена с 8 до 3, а расчётный MI увеличился с 53,4 до 57,5.
Значения доказуемо повторяются через локальный скрипт, но не выдаются за
инструментальную статистику Microsoft.
